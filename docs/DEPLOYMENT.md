# Production release gates — not yet executed

The workspace preview is a development system. Do not treat its demo administrator, seed content or temporary sandbox services as production infrastructure.

1. **Access and budget.** Obtain the owner's authorized repository, hosting projects, domain, region, budget and image-storage account. Review the current official [Vercel](https://vercel.com/pricing), [Render](https://render.com/pricing), [Aiven](https://aiven.io/pricing), and [Cloudinary](https://cloudinary.com/pricing) service terms, storage, bandwidth, database backups and compute costs. Record approved prices immediately before provisioning. No free-tier entitlement or purchase is assumed.
2. **MySQL.** Create `proxima_dining` in Aiven MySQL with utf8mb4. Use separate least-privilege runtime and migration credentials, restricted network access, backups and restore testing. Mount the provider CA certificate and set `MYSQL_SSL_CA` to its path. SQLAlchemy/PyMySQL verifies the server identity. Test TLS before traffic.
3. **Render API.** Use `backend/` as the service root and its Dockerfile, or Python 3.13 with `pip install -r requirements.txt`. Start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`. Set `APP_ENV=production`, `DATABASE_URL`, `FRONTEND_URL` (exact HTTPS origin without a trailing slash), `MYSQL_SSL_CA`, `CLOUDINARY_URL`, and a high-entropy `ADMIN_PASSWORD` as private secrets. Predeploy: `alembic upgrade head`. No production `create_all`. Provision staff once with `python -m app.core.security`, then remove the bootstrap password from the runtime environment. Never seed demonstration data in production. Remove session records when rotating credentials.
4. **Frontend.** Vercel root `frontend/`, install `npm ci`, build `npm run build`, output `dist`. Configure `VITE_API_BASE_URL` as the actual HTTPS API hostname plus `/api/v1`. Use same-site custom domains, e.g. `www.<owned-domain>` and `api.<owned-domain>`, so SameSite=Lax staff cookies work. Alternatively proxy `/api/*` to the backend under the frontend origin **before** SPA rewrites. Do not leave browser calls pointed at localhost. The bundled Vercel file handles client route fallbacks; it does not guess a backend domain.
5. **Storage.** Cloudinary accepts validated and re-encoded JPEG/PNG/WebP input (5 MB and 20 megapixel limits). Browser code sees only hosted URLs. Test an authenticated upload, attach it to a cafe or dish, change its caption/order, and check the public gallery. Deleting a gallery record removes the association, not the external asset; define storage retention/cleanup separately.
6. **Abuse controls.** Current rate limits are per-process by socket peer. Keep one worker for the local demo. Before public launch, configure proxy-aware rate limiting at the trusted edge or shared persistent limits across workers. Do not trust forwarded IP headers from arbitrary callers. Set upstream request-body and concurrency limits. Configure monitoring, request timeouts and alerting. Do not log passwords, cookies, email form bodies or secret URLs.
7. **Privacy and content.** Review jurisdiction-specific consent, data retention, unsubscribe handling and exported subscriber lists. No emails are sent automatically. Publish accurate menu, hours, dietary and contact information, and approved venue images. Replace development disclosure with launch-approved copy only after removing fictional content. API sitemap is `/api/v1/sitemap.xml`; publish its absolute production URL in robots.txt or proxy `/sitemap.xml` to it. For preview crawlers that do not execute JavaScript, consider prerendering route-specific social cards.
8. **Release test.** Confirm health, all deep-link refreshes, HTTPS, cookie attributes, staff login/logout, CSRF rejection, unpublished-item filtering, image hosting, public search, contact/subscription persistence and the full staff CRUD journey on the actual domains. Run the remaining accessibility, browser and operational checks in `PROGRESS.md`. Only then mark Phase 7 complete.
